# Compute Module 4 і 5 - вбудовування, eMMC і плати-носії

![[assets/img/rpi-cm4-cm5-scheme.png|600]]
*Рис. CM - той же Pi без роз'ємів: eMMC замість SD, радіо опційно, усе через плату-носій.*

> [!tip] Що це за нота
> Серійні вироби на Pi: коли макетка перетворюється на продукт. eMMC замість SD, свій носій під задачу, довгий життєвий цикл. Для одиниць - [[14-Devboards/01-Pi5-Flagman|флагман Pi 5]] і [[14-Devboards/02-Pi4-Robocha|робоча Pi 4]].

## 1. Мета

Зрозуміти, коли брати CM замість звичайної плати:

- варіанти: RAM, eMMC, радіо - таблиця вибору;
- IO Board як старт: що вміє еталонний носій;
- свій носій: від чого відштовхуватись;
- прошивка eMMC і оновлення в полі.

| Варіант | RAM | eMMC | WiFi/BT |
| --- | --- | --- | --- |
| CM4 Lite | 1/2/4/8 ГБ | немає (SD на носії) | опційно |
| CM4 8/16/32 ГБ | 1/2/4/8 ГБ | eMMC | опційно |
| CM5 Lite | 2/4/8/16 ГБ | немає | опційно |
| CM5 | 2/4/8/16 ГБ | 16-64 ГБ | опційно |

Правило: Lite + SD - для розробки, eMMC - для серії. Радіо беруть, коли антена на носії розведена.

## 2. Архітектура модуля

```mermaid
flowchart TB
  CM[CM4/CM5: SoC+RAM+eMMC] <-->|2x100-pin| IO[IO Board / свій носій]
  IO --> PWR[Живлення 12V/5V]
  IO --> ETH[Gigabit Ethernet]
  IO --> USB[USB2/3 хости]
  IO --> HDMI[HDMI / DSI / CSI]
  IO --> GPIO[Гребінка + свої роз'єми]
  IO --> NVME[NVMe (CM4/5)]
```

Конектори Hirose DF40 - два по 100 пінів, з'єднання платою-носієм. Механіка тримає на гвинтах і термопрокладці.

## 3. IO Board як старт

- еталонний носій: HDMI, USB, Ethernet, PCIe (CM4), SD-слот, PoE-роз'єм;
- джампери boot: eMMC vs SD vs NVMe vs USB;
- прошивка eMMC: `rpiboot` по micro-USB - модуль стає диском;
- все, що працює на IO Board, переносимо на свій носій 1:1.

## 4. Свій носій: мінімум

- живлення: PMIC-схема з даташита CM (не «як-небудь 5V»);
- копіюємо потрібне з IO Board: KiCad-проєкт відкритий;
- антена WiFi - або сертифікована доріжка, або U.FL + зовнішня;
- тестування: ICT-точки і консольний UART на край плати;
- сертифікація (CE/FCC) - для продажу, закладаємо в бюджет.

## 5. Робочий код: інвентаризація партії

```python
import subprocess
import json

def board_info():
    out = {}
    out['model'] = open('/proc/device-tree/model').read().strip('\x00')
    out['revision'] = open('/proc/cpuinfo').read().split('Revision')[1].split()[1]
    r = subprocess.run(['vcgencmd', 'get_throttled'], capture_output=True, text=True)
    out['throttled'] = r.stdout.strip()
    r = subprocess.run(['lsblk', '-J', '-o', 'NAME,SIZE,MODEL'], capture_output=True, text=True)
    out['disks'] = json.loads(r.stdout)['blockdevices']
    return out

if __name__ == '__main__':
    info = board_info()
    print(json.dumps(info, indent=2, ensure_ascii=False))
    with open('/boot/firmware/board.json', 'w') as f:
        json.dump(info, f, indent=2)
```

Скрипт інвентаризації - на кожну плату партії: модель, ревізія, тротлінг, диски. JSON лежить поруч із системою.

## 6. Оновлення в полі

- A/B-розділи: нове в запасний, перемикання прапорцем;
- `rauc` або самописний скрипт з перевіркою контрольних сум;
- відкат при невдалому boot - лічильник спроб у EEPROM;
- дельта-оновлення для повільного каналу.

## 7. Тепло і механіка серії

- термопрокладка SoC→корпус - частина конструкції, не опція;
- вібростійкість: роз'єми з фіксаторами, компаунд на важкому;
- діапазон температур: комерційний 0…50 °C, ширше - тестуємо;
- волога/пил: конформне покриття плати.

## 7.1 Сертифікація і маркування серії

- CE/FCC: тести ЕМС лабораторією, не самодіяльність;
- маркування: CE-логотип + номер нотифікованого органу;
- RoHS: компоненти і припій без свинцю, декларації постачальників;
- серійники: формат `РРРР-ММ-НННН` (продукт-рік-номер);
- штрих-код на корпусі + запис у базі партії;
- інструкція трьома мовами - вимога для роздробу;
- утилізація батарей: позначка і програма збору.

## 8. Типові помилки

| Симптом | Причина | Лікування |
| --- | --- | --- |
| eMMC не бачиться | джампер boot не в тому положенні | J2 в rpiboot, потім назад |
| WiFi немає взагалі | версія без радіо | брати варіант з WiFi або USB-донгл |
| Не стартує на своєму носії | живлення/послідовність | звірити PMIC з даташитом CM |
| SD і eMMC конфліктують | обидва носії, не той пріоритет | порядок boot в EEPROM-конфігу |
| Перегрів у корпусі | немає тепловідведення | прокладка + метал корпусу |
| Антена не ловить | доріжка без узгодження | U.FL + зовнішня антена |

## 9.1 Швидка шпаргалка CM

- Lite+SD - розробка, eMMC - серія;
- rpiboot робить модуль диском;
- радіо лише з антеною на носії;
- A/B-розділи + відкат для поля;
- термопрокладка - частина конструкції.

## 9.2 Чекліст першого носія

- живлення: послідовність шин за даташитом CM;
- boot-джампери: eMMC/SD/NVMe виставлені;
- консольний UART виведений на край плати;
- термопрокладка між SoC і корпусом;
- ICT-точки для заводського тесту;
- антена: узгодження або U.FL.
