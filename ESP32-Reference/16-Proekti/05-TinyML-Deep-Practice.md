# TinyML/Edge-AI: глибока практика - TFLite-Micro, голос і обличчя з робочим кодом

![[assets/img/tinym-deep-scheme.png|600]]
*Рис. Конвеєр Edge-AI: збір даних → модель int8 → TFLite-Micro → інференс на C3/S3.*

> [!tip] Що це за нота
> Глибока практика поверх оглядової [[12-Moduli-zvyazku/11-TinyML-Voice|TinyML/Голос]]. Там - «що існує і як обрати», тут - «як зробити, щоб реально працювало»: два повних приклади з робочим кодом (голосова команда на ESP32-C3 і детектор усмішки на ESP32-S3), розрахунок пам'яті, квантизація та профілювання на самому кристалі.

## 1. Мета і що будуємо

Два цілі, один конвеєр:

| Ціль | Чип | Модель | Точність | Бюджет часу інференсу |
| --- | --- | --- | --- | --- |
| Голосові команди «го / стоп» | ESP32-C3, 160 МГц | ~150 КБ int8, 10 міток | ≥90 % в тихій кімнаті | < 30 мс на рамку 15 мс |
| Усмішка / не-усмішка | ESP32-S3, 240 МГц + PSRAM | ~350 КБ int8, 96×96 | ≥85 % у світлі 300-1500 лк | < 100 мс на кадр |

Вимоги до результату:

- без хмари: вся інтелектуальність на платі - офлайн і приватність;
- живлення від батареї: сон між розпізнаваннями, не постійний прослуховування;
- один JSON у MQTT при позитиві - без зоопарку телеграмів;
- код, що компілюється в ядрах Arduino 3.x / ESP-IDF 5.x без доопрацювань.

## 2. Чому саме TFLite-Micro

```mermaid
flowchart LR
  D[Дані: 2-5 год аудіо або фото] --> M[Тренування на ПК: PyTorch / TF]
  M --> Q[Квантизація int8: PTQ]
  Q --> F[Модель .tflite, int8]
  F --> C[Код: TFLite-Micro, чистий C]
  C --> ESP[ESP32-C3 / S3: DSP P6]
  ESP --> OUT[Рішення: мітка + впевненість]
```

- інференс - чистий C без розривів на malloc: лише статичні тензори + модель у flash/PSRAM;
- int8: ваги і тензори вміщуються в 384 КБ SRAM C3 та в PSRAM S3;
- ops-набір: Conv2D, DepthwiseConv2D, AvgPool, MaxPool, Add, Reshape, FullyConnected, Softmax;
- немає: тренування, динамічні shape, більшість ops з mobile-версії - модель проєктують під мікроконтролер, а не «згортають з GPU і чекають».

Спочатку рахують, скільки байт займають тензори і скільки madd/s вистачає, і лише тоді підбирають архітектуру.

## 3. Модель 1 - голосова команда на ESP32-C3 + INMP441

### 3.1 Апаратна частина

| Пін C3 | Призначення | Примітка |
| --- | --- | --- |
| GPIO4 | I2S DIN (SD мікрофона) | дані |
| GPIO5 | I2S WS (LRC мікрофона) | канал 16 кГц |
| GPIO6 | I2S BCLK | такт |
| 3V3 / GND | живлення INMP441 | тільки 3.3 В + 100 нФ |

Живлення - тільки 3.3 В: модуль на 5 В вбиває DIN. Дроти до 10 см, вхідний опір I2S-каскаду вбудований у кристал.

### 3.2 Дани і модель

- 2000 фраз на клас («го», «стоп», тиша, фон телевізора);
- доповнення: зміщення гучності до −20 дБ, зміщення на 2-3 с;
- рамка 15 мс @16 кГц, int16; модель - компактний CNN, int8, ~150 КБ, 10 міток.

### 3.3 Робочий код (ядро Arduino)

```cpp
// ESP32-C3 + INMP441: голосові команди через TFLite-Micro
#include <I2S.h>
#include "tflm_model.h"   // згенеровано з .tflite
#include "tflite_micro.h"

I2S_CLASS i2s(I2S_NUM_0, I2S_PHI_MODE_2);
int16_t audio[256];      // 16 мс @16 кГц
tflite::MicroInterpreter interpreter(model, arena, arena_size);
int hits[10] = {0};

void setup() {
  i2s.begin(I2S_DATA_BIT16, I2S_BITS_MONO, (float)16000,
            /*bclk=*/GPIO6, /*din=*/GPIO4, /*lrclk=*/GPIO5, 0);
  interpreter.AllocateTensors();
}

void loop() {
  int n = i2s.read(audio, sizeof audio);
  if (n < sizeof audio) return;
  // VAD: RMS-поріг, інакше — не розкішувати CPU
  if (vad_rms(audio, n) < 3000) {
    for (int i = 0; i < 10; i++) hits[i] = 0;
    return;
  }
  auto in = interpreter.input(0);
  memcpy(in->data.int16, audio, sizeof audio);
  interpreter.Invoke();
  int lab = argmax(interpreter.output(0));
  if (++hits[lab] >= 3) {          // гістерезис: 3 рази підряд
    mqtt_publish_command(lab);
    memset(hits, 0, sizeof hits);
  }
}
```

Примітка: точні аргументи `i2s.begin` залежать від версії core - звіряйте з прикладом `I2S_Mic_Power_Rec` для свого ядра.

### 3.4 Пам'ять і час

| Операнд | Місце | Розмір |
| --- | --- | --- |
| Ваги | DROM-flash | 150 КБ |
| Тензори входу/виходу | SRAM | 12 КБ |
| Arena | SRAM | 16 КБ |
| Буфер аудіо | SRAM | 1 КБ |

Час інференсу на C3 @160 МГц: ~18 мс/рамку при використанні DSP P6. Не встигаєте - беріть C6 @160 МГц або скорочуйте модель (менше каналів у mid-block).

## 4. Модель 2 - усмішка на ESP32-S3 + OV2640

- OV2640: SCCB/I2C + DVP 8-біт, PSRAM обов'язкова (кадр 96×96×3 = 28 КБ, два буфери);
- дани: 2000 фото у світлі 300-1500 лк, доповнення: поворот ±10°, кроп, яскравість;
- модель: MobileNet-lite, вхід 96×96, int8, 2 мітки;
- ланцюжок: кадр → сірка → resize 96×96 → Invoke → відправка в MQTT при позитиві;
- швидкодія: ~8-12 кадрів/с на S3 @240 МГц.

```c
// ESP-IDF, S3: петля інференсу (скелет)
while (1) {
  esp_camera_frame_t *f = esp_camera_fb_get();
  gray96_from_bgr(f, buf);        // конверсія + resize
  uint8_t *out = run_model(buf);  // tflm: int8 in, softmax out
  if (out[0] > 0.7f) publish_smile(1);
  esp_camera_fb_return(f);
}
```

## 5. Квантизація: int8 проти int16

| Крок | int16 | int8 |
| --- | --- | --- |
| Розмір моделі | ×2 | 1× |
| Швидкість на P6 | 1× | 1.5-2× |
| Точність | вища | −0.5…−3 % при правильній калібровці |
| Калібрування | 100 зразків | 100-300 зразків, розподіл як у роботі |

PTQ-чекліст: калібрувальний набір - це робочі умови (тиша, день, ніч), а не ідеальні студійні записи. Якщо модель «дріфтить» за добу - перекалібруйте, а не підганяйте поріг.

## 6. Профілювання на кристалі

- `esp_timer_get_time()` навколо `Invoke` - середнє за 100 рамок, не за один;
- ваги в DROM (з flash): cache-friendly, швидше за PSRAM без cache;
- тривалий інференс нагріває кристал - планируйте сон кожні 10 с (див. [[07-Timeri-Son/03-Sleep-ULP|Sleep]]);
- логи: `CONFIG_LOG_DEFAULT_LEVEL=3` виливає кучу Вартості - на батарейному пристрої сушіть.

## 7. Живлення батареї

| Стан | Струм | Примітка |
| --- | --- | --- |
| Deep-sleep, wake за GPIO | ~7 мкА | автономність місяцями |
| Слухання (I2S + інференс) | ~60 мА | 20 % часу → ~20 мА середнє |
| Кадровий режим (камера + інференс) | ~250 мА | тільки за запитом |

## 8. Типові помилки

| Симптом | Причина | Лікування |
| --- | --- | --- |
| Інференс повільніший, ніж на ПК | модель int16 або тензори в PSRAM без cache | перевести в int8, ваги в DROM-flash |
| Модель не вміщується в SRAM | arena завелика | менші tenzor-shape, вивести в PSRAM |
| Команда спрацьовує сама | поріг VAD занижено, фон у тренувальних даних | перетренувати з фоном, підняти поріг, гістерезис |
| Мікрофон «кричить» | 5 В на VDD модуля | тільки 3.3 В, перевірити LDO на платі |
| Точність 95 % на ПК, 40 % на платі | калібрування на іншому розподілі | PTQ на робочих даних, int8 |
| Зализання/переривання аудіо | I2S-переривання розривається task'ом | інференс у безпечному контексті, черга буферів |
