# Compute Module 4 and 5 - Embedding, eMMC and Carrier Boards

![[assets/img/rpi-cm4-cm5-scheme.png|600]]
*Fig. CM is the same Pi without connectors: eMMC instead of SD, optional radio, everything through a carrier board.*

> [!tip] What this note is
> Serial products on Pi: when a breadboard turns into a product. eMMC instead of SD, a custom carrier for the task, a long lifecycle. For single units - [[EN/14-Devboards/01-Pi5-Flagship.en|Pi 5 flagship]] and [[EN/14-Devboards/02-Pi4-Workhorse.en|Pi 4 workhorse]].

## 1. Goal

Understand when to take a CM instead of a regular board:

- options: RAM, eMMC, radio - a choice table;
- IO Board as a start: what the reference carrier can do;
- a custom carrier: what to start from;
- eMMC firmware and field updates.

| Option | RAM | eMMC | WiFi/BT |
| --- | --- | --- | --- |
| CM4 Lite | 1/2/4/8 GB | none (SD on carrier) | optional |
| CM4 8/16/32 GB | 1/2/4/8 GB | eMMC | optional |
| CM5 Lite | 2/4/8/16 GB | none | optional |
| CM5 | 2/4/8/16 GB | 16-64 GB | optional |

Rule: Lite + SD for development, eMMC for production. Take radio when the carrier antenna is laid out.

## 2. Module architecture

```mermaid
flowchart TB
  CM[CM4/CM5: SoC+RAM+eMMC] <-->|2x100-pin| IO[IO Board / custom carrier]
  IO --> PWR[12V/5V power]
  IO --> ETH[Gigabit Ethernet]
  IO --> USB[USB2/3 hosts]
  IO --> HDMI[HDMI / DSI / CSI]
  IO --> GPIO[Header + custom connectors]
  IO --> NVME[NVMe (CM4/5)]
```

Hirose DF40 connectors - two of 100 pins, joined by the carrier board. Mechanics holds on screws and a thermal pad.

## 3. IO Board as a start

- reference carrier: HDMI, USB, Ethernet, PCIe (CM4), SD slot, PoE connector;
- boot jumpers: eMMC vs SD vs NVMe vs USB;
- eMMC firmware: `rpiboot` over micro-USB - the module becomes a disk;
- everything that works on the IO Board ports 1:1 to your own carrier.

## 4. Custom carrier: minimum

- power: the PMIC circuit from the CM datasheet (not "some 5V");
- copy what is needed from the IO Board: the KiCad project is open;
- WiFi antenna - either a certified trace or U.FL + external;
- testing: ICT points and a console UART on the board edge;
- certification (CE/FCC) for sale, budget it in.

## 5. Working code: batch inventory

```python
import subprocess
import json

def board_info():
    out = {}
    out['model'] = open('/proc/device-tree/model').read().strip('\x00')
    out['revision'] = open('/proc/cpuinfo').read().split('Revision')[1].split()[1]
    r = subprocess.run(['vcgencmd', 'get_throttled'], capture_output=True, text=True)
    out['throttled'] = r.stdout.strip()
    r = subprocess.run(['lsblk', '-J', '-o', 'NAME,SIZE,MODEL'], capture_output=True, text=True)
    out['disks'] = json.loads(r.stdout)['blockdevices']
    return out

if __name__ == '__main__':
    info = board_info()
    print(json.dumps(info, indent=2, ensure_ascii=False))
    with open('/boot/firmware/board.json', 'w') as f:
        json.dump(info, f, indent=2)
```

An inventory script for every board of the batch: model, revision, throttling, disks. The JSON sits next to the system.

## 6. Field updates

- A/B partitions: new into the spare, switch with a flag;
- `rauc` or a self-written script with checksum verification;
- rollback on failed boot - an attempt counter in EEPROM;
- delta updates for a slow channel.

## 7. Production heat and mechanics

- SoC-to-case thermal pad is part of the design, not an option;
- vibration resistance: locking connectors, compound on heavy parts;
- temperature range: commercial 0 to 50 °C, wider needs testing;
- moisture/dust: conformal board coating.

## 7.1 Production certification and marking

- CE/FCC: EMC tests by a lab, not DIY;
- marking: CE logo + notified body number;
- RoHS: lead-free components and solder, supplier declarations;
- serials: `PPPP-YY-NNNN` format (product-year-number);
- barcode on the case + a batch database record;
- a three-language manual - a retail requirement;
- battery disposal: a mark and a collection program.

## 8. Common issues

| Symptom | Cause | Fix |
| --- | --- | --- |
| eMMC not seen | boot jumper in the wrong position | J2 to rpiboot, then back |
| No WiFi at all | version without radio | take a WiFi variant or a USB dongle |
| Does not start on a custom carrier | power/sequencing | match the PMIC to the CM datasheet |
| SD and eMMC conflict | both media, wrong priority | boot order in the EEPROM config |
| Overheat in the case | no heat removal | pad + metal case |
| Antenna does not catch | trace without matching | U.FL + external antenna |

## 9.1 CM quick cheat sheet

- Lite+SD for development, eMMC for production;
- rpiboot turns the module into a disk;
- radio only with an antenna on the carrier;
- A/B partitions + rollback for the field;
- the thermal pad is part of the design.

## 9.2 First carrier checklist

- power: bus sequence per the CM datasheet;
- boot jumpers: eMMC/SD/NVMe set;
- console UART on the board edge;
- thermal pad between SoC and case;
- ICT points for the factory test;
- antenna: matching or U.FL.
