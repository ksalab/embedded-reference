# RP2040 and RP2350 - PIO state machines, ADC and sleep of Pico microcontrollers

![[assets/img/rpi-rp2040-rp2350-scheme.png|600]]
*Fig. RP2040/RP2350: two cores, PIO state machines instead of fixed peripherals, ADC and USB - all for a few dollars.*

> [!tip] What this note is
> Another class of devices: not Linux but deterministic real time. PIO is the main trick: UART/SPI/I2S/DVI with software state machines. Boards: [[EN/14-Devboards/03-Pico-W-Family.en|Pico family]], environment: [[EN/00-Start/05-Vibir-seredovischa.en|environment choice]].

## 1. Goal

To master Pico as hard peripherals and a standalone node:

- how RP2350 is better than RP2040 and whether it is worth switching;
- PIO: what it is and three typical uses;
- ADC, die temperature, USB device;
- microamp sleep for battery nodes.

| Parameter | RP2040 | RP2350 |
| --- | --- | --- |
| CPU | 2×M0+ 133 MHz | 2×M33 150 MHz (or RISC-V) |
| RAM | 264 KB | 520 KB |
| Flash | external, up to 16 MB | external, up to 16 MB |
| PIO | 2 blocks × 4 state machines | 3 blocks × 4 state machines |
| ADC | 12-bit, 4 channels + temperature | 12-bit, improved |
| USB | device 1.1 | device + host |
| Security | none | Secure Boot, OTP |

## 2. Architecture

```mermaid
flowchart TB
  C0[Core 0: logic] <-->|FIFO| C1[Core 1: real time]
  C0 <--> PIO[PIO state machines: WS2812/I2S/DVI]
  C0 <--> ADC[12-bit ADC + temperature]
  C0 <--> USB[USB-CDC/HID]
  PIO --> LED[NeoPixel strip]
  PIO --> DVI[DVI video (RP2350)]
  ADC --> SENS[Sensors]
```

PIO state machines run independently of the cores: start a 32-instruction program and forget it, hardware holds the timings.

## 3. PIO: three hits

- WS2812 NeoPixel: accurate 800 kHz with no CPU blocking;
- I2S audio: stream to DAC in the background;
- DVI/HDMI video (PicoDVI): 640×480 in software - RP2350 unlocks it fully;
- the program is written in PIO assembler (9 commands) or with the `pioasm` generator.

## 4. ADC and power supply

- 4 channels + built-in die temperature sensor;
- 3.3V reference - accuracy as of the regulator, calibrate against a known source;
- VSYS/4 on ADC3 - measure own battery with no divider;
- power: 5V USB or 1.8-5.5V on VSYS (battery directly!);
- sleep: dormant with RTC - single microamps, wake-up on GPIO.

## 5. Working code (MicroPython)

```python
from machine import ADC, Pin
from rp2 import PIO, StateMachine, asm_pio
import time

@asm_pio(sideset_init=PIO.OUT_LOW, out_shiftdir=PIO.SHIFT_LEFT,
         autopull=True, pull_thresh=24)
def ws2812():
    T1 = 2
    T2 = 5
    T3 = 3
    wrap_target()
    label("bitloop")
    out(x, 1)               .side(0)    [T3 - 1]
    jmp(not_x, "do_zero")   .side(1)    [T1 - 1]
    jmp("bitloop")          .side(1)    [T2 - 1]
    label("do_zero")
    nop()                   .side(0)    [T2 - 1]
    wrap()

sm = StateMachine(0, ws2812, freq=8000000, sideset_base=Pin(0))
sm.active(1)

adc = ADC(26)

while True:
    raw = adc.read_u16()
    volt = raw * 3.3 / 65535
    print("ADC", raw, volt)
    sm.put(bytes([0, 255, 0]) * 8)
    time.sleep(1)
```

The same PIO state machine spins NeoPixel while Python reads the ADC - no timing conflicts.

## 6. Working code (C SDK)

- `pico-sdk`, CMake, the `pico_project.py` script generates the skeleton;
- `pioasm` compiles PIO programs into headers;
- `sleep_run_from_xosc` + dormant - minimal consumption;
- multicore: `multicore_launch_core1` - second core for drivers;
- SWD debugging through a second Pico (Picoprobe) for 4 dollars;
- blink example with PIO - first test after toolchain build.

## 7. W versions: radio on board

- Pico W / Pico 2 W: WiFi + BT through the CYW43439 chip;
- MicroPython: `network` module, MQTT - `umqtt.simple`;
- C SDK: lwIP included, TCP/UDP examples;
- antenna on the board - do not cover with the case metal;
- no deep-sleep with WiFi kept - we wake up and reconnect;
- BT: classic SPP and BLE peripherals (depends on CYW43 firmware).

## 7.1 Battery power in detail

- Li-ion 3.7V to VSYS directly: the 1.8-5.5V range covers discharge;
- charging - a separate TP4056, Pico cannot charge;
- monitoring: ADC3 measures VSYS/4, cut-off threshold 3.0V;
- sleep between measurements: dormant + RTC alarm, microamps on average;
- 5V solar panel + TP4056 - months of autonomy;
- supercapacitor instead of a battery - for frequent short cycles.

## Common issues

| Symptom | Cause | Fix |
| --- | --- | --- |
| PIO cannot keep up | state machine frequency too low | `freq` for the protocol (WS2812 - 8 MHz) |
| ADC drifts | 3.3V reference wobbles from USB | separate LDO or calibration against TL431 |
| USB not seen | charge-only cable without data | full cable, check D+/D- |
| Second core hangs | no `fifo` sync | FIFO queue + flags, not shared variables |
| WiFi drops | antenna covered | take the board out of the metal case |
| C SDK does not build | no ARM toolchain | `arm-none-eabi-gcc` per the SDK guide |
